# 0.9.5 并行重新分析与分析速度模式规格

## 目标

在不暂停、不改序、不接管主投递队列的前提下，为已有完整分析输入的单个岗位提供独立重新分析；同时以统一配置表达 AI 分析速度，由各协议能力适配器安全映射到厂商支持的推理参数。

## 行为边界

- 岗位行操作顺序为“重新分析、定位”；重新分析复用该岗位最近一次已采集的 JD 请求输入，不再次点击 BOSS 职位卡片。
- 独立重新分析不修改主队列的 `analyzing`、`analysisRunId`、批次、暂停状态或沟通状态，只替换该岗位的分析结果。
- 同一岗位防止重复请求；岗位已离开页面、尚无分析输入、正在主分析或正在沟通时按钮禁用。
- 独立重新分析不自动发起沟通。新的分数用于显示和后续用户决策，避免并发响应造成意外投递。
- 分析速度模式为 `fast`、`balanced`、`accurate`，默认 `fast`，旧配置自动采用该默认值。
- 只有明确识别并确认支持的厂商/模型才发送推理控制参数；未知 OpenAI 兼容接口不接收任何厂商私有 thinking 参数。

## 速度模式语义

- 极速：关闭 thinking；无法关闭时使用最低官方推理级别。
- 平衡：使用官方低推理级别；不支持时省略参数并使用服务商默认。
- 精确：省略推理限制，使用服务商默认或官方高推理级别，不向未知接口猜测参数。

DeepSeek V4 只公开 `high/max` 两档 thinking effort，因此平衡使用 `high`、精确使用 `max`；Gemini 2.5 使用 token budget，Gemini 3 使用模型支持的命名等级；固定推理模型与未知模型省略参数。

## 验证

- 单元/集成测试证明重分析与主队列状态隔离、同岗位防重和结果精确回写。
- 协议测试覆盖 DeepSeek、Gemini、OpenAI Responses、Anthropic 与未知 OpenAI 兼容接口的三种模式映射。
- 完整测试、语法和 Manifest 校验通过。
- 性能测试记录并行请求启动开销、JSON 本地修复基准和主队列无额外固定等待。
- Edge 实测确认按钮布局、配置保存以及重分析期间主队列状态不被暂停；真实沟通动作与分析测试分离。
