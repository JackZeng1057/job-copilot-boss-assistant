# 综合评分与排除岗位规范

## 目标

为不同用户提供一致的评分框架，同时允许每位用户独立声明绝不投递的职业类型。源码不得预设个人目标方向或排除岗位。

## 综合评分

AI 参考用户配置、所有已勾选简历、完整 JD、岗位门槛、地点和机会质量，给出最终 0-100 分：

| 维度 | 分值 |
| --- | ---: |
| 方向相关性 | 30 |
| 简历证据 | 25 |
| 岗位门槛 | 20 |
| 地理位置 | 10 |
| 机会质量 | 15 |

扩展只把分数限制在 0-100，并与用户设置的最低分比较。与目标方向、简历主线和可迁移能力都基本无关的岗位，即使门槛低，也应低于 50 分。

### 直接匹配校准

1. 先判断职业方向，再评估经验、学历、地点等门槛。岗位标题或核心职责与用户配置的目标方向完整语义直接对应时，`target_alignment=direct`，方向相关性通常应为 24-30 分。
2. 方向直接匹配后，不得因为工作年限、公司行业、某个次要技能或岗位级别不足而反向降低方向相关性。
3. 方向直接匹配，且简历至少有一项同方向的真实工作、实习、项目或技能证据时，在未命中排除项、地点可接受且不存在硬性冲突的情况下，总分应进入 60-79 分的值得投递/沟通区间，而不是停留在 50 分左右。
4. 经验年限不符、应届身份不符、“高级/资深”标题本身都不是硬性冲突。硬性冲突必须是 JD 明确要求且候选人确实无法满足的准入条件，并写入 `risks`。
5. 同一缺口只能归入一个最贴切的评分维度扣一次。经验年限与应届身份只影响岗位门槛中的 0-6 分，不得再次扣减方向相关性、简历证据或机会质量。
6. 模型应先分别确定五个维度的分数并求和，再输出最终 `score`，不得凭模糊的整体印象另给一个更低的总分。

## 配置边界

- `目标方向/关键词`：用户希望寻找的岗位方向，是评分强信号。
- `绝不投递岗位/职业类型`：明确命中后无条件跳过，优先级高于分数。
- `额外分析提示词`：补充初级友好度、工作方式、行业偏好等个性化条件。
- 所有字段默认留空或使用中性默认值，只保存在当前用户浏览器中。

## 排除岗位语义规则

1. 先依据标题和完整 JD 概括岗位主要职业类型。
2. 将主要职业类型与用户排除项逐项进行完整语义比较。
3. 只有岗位核心工作明确属于排除职业类型时才算命中。
4. 共享宽泛词不算命中：
   - 技术支持不等于客户支持。
   - 产品运营不等于直播运营。
   - 市场策划不等于电话销售。
   - 客户服务不等于保险销售。
5. 少量附带任务、公司行业相似或标题含糊时不得误判为排除。
6. 排除列表为空时永远不触发排除。

## 输出契约

```json
{
  "score": 0,
  "decision": "recommend|manual_review|skip",
  "excluded": false,
  "exclusion_match": "",
  "exclusion_reason": "",
  "occupation_family": "",
  "target_alignment": "direct|transferable|unrelated|unclear",
  "reasons": [],
  "risks": [],
  "resume_tips": [],
  "location_fit": "good|acceptable|unclear|poor",
  "greeting": "",
  "qa": []
}
```

扩展处理规则：

1. `excluded=true`：强制 `decision=skip`，最终分最高为 19。
2. `excluded=false` 且分数达到用户最低分：允许进入自动沟通候选。
3. 未达到最低分：不自动沟通。

## 测试要求

- 排除配置能保存、读取并进入 AI 请求。
- 默认排除列表为空，不影响普通岗位。
- 明确命中的排除岗位即使模型返回高分也必须跳过。
- 相邻但不同的职业类型不得因为共享宽泛词被排除。
- 未排除岗位只按最终分和用户最低分判断。
- 已勾选简历为空时不得回退到未勾选简历。
- 目标方向直接命中时，提示词明确锁定 24-30 分的方向相关性。
- 直接命中且简历存在同方向证据时，无硬性冲突的结果应进入 60-79 分区间。
- 同一缺口不得跨多个评分维度重复扣分；经验与应届差距只影响门槛中的 0-6 分。
