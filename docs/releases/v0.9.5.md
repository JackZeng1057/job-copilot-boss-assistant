# Job Copilot v0.9.5

0.9.5 是 1.0 前的导航安全与吞吐优化版本。

## 重点变化

- 求职偏好新增可选工作经验年限，以及“未设置 / 应届生 / 非应届生”三态身份；统一 AI 评分中该项只占 0-6 分，用于小幅反映 JD 门槛，不会单独淘汰岗位。
- 读取完整 JD 或沟通期间，如果 BOSS SPA 将原职位列表标签切到 `/job_detail/` 或 `/web/geek/chat`，扩展会在主世界持续拦截并暂停恢复。
- 后台提供多阶段标签导航兜底，覆盖内容脚本已短暂恢复后再次逃逸的延迟路由，并保证一次异常最多执行一次历史后退。
- 如果 BOSS 使用替换路由导致浏览器没有可用历史，后台仅在确认仍处于异常路由后，使用同一标签恢复已保存的职位列表 URL，不创建详情标签。
- 所有支持的 AI 协议统一使用紧凑评分 Schema、输入预算和原生结构化输出；允许省略上限的协议沿用服务商默认值，Anthropic 仅保留协议强制要求的 `max_tokens`。
- 通过协议能力层降低批量评分的可选推理强度，并取消第二次模型 JSON 修复请求；单次 AI 请求最长等待 60 秒。
- 配置页新增统一“分析速度模式”：极速、平衡、精确。后台只对官方域名和明确支持的模型映射推理参数，未知兼容接口保持协议中立。
- 每个已有分析输入的岗位在“定位”左侧新增“重新分析”；它复用最近一次完整 JD 输入并独立并发执行，不暂停、不改序、不接管主队列，也不会自动沟通。
- token 用量只进入本地诊断日志，不在插件岗位列表显示。
- 常见代码围栏、尾逗号、单引号、未加引号键、Python 布尔值、控制字符和普通结构残缺在本地修复；无法识别时直接保留岗位并失败，不再追加模型修复请求。服务商声明输出截断时同样不使用半份评分。
- 达标后沟通过渡为约 3 秒，岗位间保留约 5 秒节奏；固定节奏不包含 JD 读取和 AI 响应耗时。
- 日志会区分 JD 读取耗时、AI 请求耗时及是否发生本地 JSON 容错；格式异常会直接失败并保留岗位，不再额外消耗一轮模型 token。
- 原始模型 JSON 不会写入电脑文件或浏览器存储；会话只保留最多 50 个岗位的精简判断字段。
- 用户手动点击“立即沟通”时直接使用当前已显示的职位详情按钮，不另开职位详情标签；使用 BOSS job ID 精确对应队列岗位，并在按钮变为“继续沟通/再次沟通”等成功状态后才移除该岗位。已有会话在独立消息标签打开。
- 手动点击保留原始可信浏览器事件供 BOSS 执行，不再用合成点击重放；“已发送”弹窗中的“留在此页”也作为明确成功闭环，完成后只移除对应岗位。
- 职位列表标签与消息标签强制隔离；受保护职位标签若因 BOSS SPA 意外进入消息页，后台会自动后退，运行中的批次同时暂停。

## 升级后首次使用

1. 在扩展管理页重新加载 0.9.5。
2. 手动刷新已打开的 BOSS 职位列表页，使新版内容脚本生效。
3. 先用少量岗位观察一轮；如看到“已自动后退并暂停”，确认列表恢复后再点击继续。

> 不同厂商和模型的 thinking 控制方式并不兼容。0.9.5 只对官方域名和明确识别的模型族发送已映射参数；自定义和未知兼容接口不会收到猜测出的私有参数。

> token 统计来自各服务商响应的 usage 数字，仅用于诊断且不在面板展示。插件不会为了统计保存完整模型响应、简历或 JD。
