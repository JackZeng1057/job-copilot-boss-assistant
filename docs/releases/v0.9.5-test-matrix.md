# Job Copilot 0.9.5 全量验收矩阵

## 自动化回归

- 扩展版本、Manifest V3、Edge/Chromium 后台存储兼容与新版脚本接管。
- 职位列表标签导航保护：卡片 SPA 路由、详情页、消息页、`history.pushState`、`replaceState`、`window.open` 与后台二级恢复。
- 手动“立即沟通”：使用当前详情按钮、按 BOSS job ID 精确匹配、成功后只删除对应岗位、失败保留、序号连续重排。
- 自动沟通：职位页与消息页独立、临时沟通标签静默创建/关闭、已有沟通识别、失败/限流/安全验证保护。
- 15 岗队列：单次启动、暂停/继续、换页、批次等待、失败恢复、下一个达标岗位、关闭检测。
- AI：四类协议、原生结构化输出、输出上限策略、输入预算、60 秒超时、截断保护、本地 JSON 容错、无第二次模型修复。
- 通用分析速度：极速/平衡/精确的保存、默认迁移，以及 DeepSeek、OpenAI、Gemini、Anthropic、未知兼容接口的安全能力映射。
- 评分：目标方向、排除方向、职业语义、城市、经验年限与应届状态 0-6 分低权重。
- 单岗位并行重新分析：按钮顺序、输入复用、同岗位防重、结果精确回写、失败保留旧结果、主队列状态不变。
- Token 与存储：界面不展示 token；日志只保存数字；不保存原始响应；会话最多 50 个精简分析。
- 性能：固定等待、DOM 扫描/渲染热路径、本地 JSON 修复吞吐和分析存储体积。

## Edge 实际功能验收

1. 重新加载 0.9.5，并刷新已打开的 BOSS 职位列表页。
2. 核对配置页经验年限、应届状态和三档分析速度的保存与恢复。
3. 扫描一轮 15 个互联网岗位，观察职位列表标签始终不变成详情页或消息页。
4. 在主队列分析期间，对一个已有输入的其他岗位点击“重新分析”，确认两者同时运行且队列不暂停、不改序。
5. 手动点击一个当前详情的“立即沟通”，确认不新开职位详情、按钮变为继续/再次沟通后只移除该岗位，剩余序号连续。
6. 打开“消息”，确认只在独立消息标签显示，职位列表标签仍保留筛选和运行状态。
7. 记录 15 岗总耗时、每岗 AI 耗时、输出/推理 token 数字、JSON 本地修复次数和二次模型修复次数（应为 0）；这些数字只从诊断日志读取，不显示在岗位列表。
8. 抽查经验/应届要求不同的 JD，确认理由或风险中有低权重体现，且不会单独触发淘汰。

涉及真实“立即沟通”的步骤只使用用户明确指定的测试岗位与现有招呼内容，不擅自扩大投递范围。
