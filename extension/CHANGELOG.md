## 1.0.0（2026-08-13）

### 稳定版

- 自动“立即沟通”使用 Chromium Debugger API 派发浏览器原生可信点击；严格校验发起标签、BOSS 页面地址、岗位 URL、坐标范围和点击命中元素，并在一次点击后立即释放调试会话。
- 原生点击前临时让 Job Copilot 自身浮层不参与命中测试，保留 BOSS 登录、安全验证和其他页面遮罩的阻断能力；短暂等待平滑滚动和布局稳定后再决定是否点击。
- 沟通失败的达标岗位新增“重试沟通”，复用已有评分，仅处理当前岗位并在完成后保持自动队列暂停。
- 原生沟通点击前先等待当前岗位标记写入 Service Worker 会话；写入失败时不点击，异常跳转恢复时会准确标记对应岗位并成对清理会话字段。
- 达标线允许使用 0 分，AI prompt 与内容脚本队列始终使用同一阈值，不再把合法的 0 错当成默认 60 分。
- AI 空正文最多自动重试一次；可从部分兼容接口的 `reasoning_content` 恢复有效 JSON，并通过结构校验跳过正文前的元数据对象或推理噪声。
- 直接匹配的职业方向固定为高相关区间；工作年限、应届身份、岗位级别和次要技能缺口不再反向扣减方向分或跨维度重复惩罚。
- 移除批量评分结果中全项目未使用的 `resume_tips`、`qa` 字段，以及已退出运行路径的隔离沟通和 JSON 修复遗留代码。
- 结构化输出的数组长度和分数范围改由本地归一化统一约束，兼容只支持部分 JSON Schema 关键字的 AI 服务。
- 简历导入支持 Word（.docx）：直接读取正文并保留段落、制表符与换行；旧版 .doc、Pages、RTF 等格式给出明确提示，伪装成 .txt 的二进制文件会被拦截，不再把乱码静默存成简历。
- 已关闭岗位的键集合与已完成集合采用同一上限，长时间连续投递不再让内存集合与会话存档逐渐偏离。
- 内容脚本按职责拆分为岗位抓取、面板布局和主流程三个文件，分析主循环收敛到 146 行。
- 刷新职位页或列表被替换后，批次计数从第 1 批重新开始；旧会话的批次进度只在确属同一份列表时才恢复，不再出现「第 7 批 · 总数 15 个」这类互相矛盾的面板信息。
- 「继续沟通」不再被当成「该岗位已投递」：该文案反映的是与招聘者账号已有会话，同一 HR 的其他岗位也会显示，自动队列和手动点击都曾因此直接跳过、只打开消息页并把岗位移出队列。现在两条路径都照常发起沟通；同时，点击前就已是「继续沟通」的按钮不再被当作本次沟通成功的证据，只认 BOSS 的显式发送确认或真实进入聊天。
- 后台标签页被浏览器限速（隐藏 5 分钟后定时器降到每分钟一次）时，按次数重试的详情匹配与原生点击预检不再空转数分钟后把岗位误判为「需人工处理」：现在会识别出实际耗时远超预期的定时器，保留岗位并在标签回到前台后重试，日志新增每次沟通的分阶段耗时、限速状态与标签可见性。
- 沟通结果的确认窗口改为在原生点击**送达之后**才开始计时。此前 15 秒的确认窗口与点击派发共用同一段计时，而 `chrome.debugger` 的输入命令要等 BOSS 渲染线程确认才返回；页面卡顿时一次点击耗时 95 秒，BOSS 实际上没有获得任何确认时间，岗位却被记为「未返回明确的沟通成功确认」。
- 原生点击在 Service Worker 侧加入 20 秒上限：调试会话连接与点击序列分别限时，超时后会先补发鼠标释放再断开调试会话，不会留下按住不放的鼠标；导航保护的时长上限相应放宽到覆盖「点击 + 确认」全程。
- 点击未能送达不再等同于 BOSS 拒绝：这类岗位保留在队列中自动重试一次，仍失败才交人工确认，并给出「页面长时间无响应」的真实原因；沟通计时日志新增 dispatchMs。
- 延续并整合 0.9.5 的导航保护、多 AI 协议、结构化输出、输入预算、分析速度模式、单岗位重新分析、本地 JSON 容错和会话存储边界，作为首个稳定版发布。

### 质量保障

- 自动化回归扩展到 56 个测试脚本，覆盖原生点击协议、沟通标记持久化与存储失败、浮层遮挡、沟通单岗重试、空正文重试、reasoning JSON 恢复、结构校验、队列选择和评分校准。
- Edge 使用隔离临时配置成功加载 Manifest V3 扩展和配置页，页面无 JavaScript 异常。
- 发布前通过完整测试、JavaScript 语法检查、JSON 校验、压缩包内容校验、`git diff --check` 和凭据模式扫描。

## 0.9.5（2026-08-05）

### 修复

- 求职偏好新增“工作经验年限”和“是否应届”配置；所有 AI 厂商共用同一评分规则，对照 JD 的经验/应届要求，并将该因素限制为总分 0-6 分，不能单独触发淘汰。
- 修复岗位卡片模拟点击仅阻止原生链接、却无法阻止 BOSS SPA 路由进入 `/job_detail/` 的导航保护漏洞。
- 内容脚本在点击后同步及等待期间检测详情路由，自动执行浏览器后退、停止当前读取并暂停自动投递。
- 临时主页面导航保护同时拦截 BOSS 通过 `window.open` 打开的详情/消息窗口，避免手动沟通时出现详情标签闪开又关闭。
- 后台监听自动投递所属标签的详情页逃逸，确认内容脚本尚未恢复后才执行第二层后退，避免重复后退越过职位列表。
- 后台恢复窗口始终同时复查消息页和详情页，覆盖两种异常路由在等待期间相互切换的竞态。

### 性能

- OpenAI Chat 兼容、OpenAI Responses、Anthropic Messages 和 Gemini 四类协议统一使用紧凑评分 Schema 与原生结构化输出；允许省略上限的协议恢复服务商默认值，Anthropic 仅保留规范强制要求的 `max_tokens`。
- 评分请求通过统一能力层使用低延迟推理配置，并取消第二次模型 JSON 修复请求；单次 AI 请求最长等待 60 秒。
- 配置页新增统一“分析速度模式”（极速 / 平衡 / 精确）；仅对官方域名和明确识别的模型族映射推理参数，未知兼容接口保持协议中立。
- DeepSeek V4、OpenAI 推理模型和 Gemini 思考模型分别使用各自受支持的速度映射；不支持或尚未识别的模型不发送对应参数。
- 不再强制发送 `temperature` 等并非所有新模型都支持的采样参数。
- 简历输入限制为 16000 字符、JD 输入限制为 7000 字符；仅异常超长时保留首尾并标注省略。
- 批量评分不再要求生成未使用的 `resume_tips`、`qa` 字段，理由和风险数量也设为紧凑上限。
- 统一记录各协议返回的输入、可见输出、reasoning/thinking、缓存与总 token，仅用于本地诊断，不在插件岗位列表展示，也不保存原始响应。
- 常见畸形 JSON 改为本地确定性修复；本地无法识别时直接保留岗位并报告失败，不再发起第二次模型修复请求。
- 四类协议统一识别服务商声明的 token 上限截断；分析响应被截断时安全停止该岗位，不把补全后的半份 JSON 用于自动沟通。
- 手动点击“立即沟通”改为使用当前已显示的详情按钮，不再打开职位详情临时标签；以 BOSS job ID 精确绑定队列岗位，禁止公司名宽松匹配，且只有按钮变为“继续沟通/再次沟通”等明确状态后才移除正确岗位。已有会话始终在独立消息标签打开。
- 手动沟通删除目标岗位时不再废弃主队列正在分析的另一个岗位请求，避免一次手动点击造成其他岗位状态消失或重复分析。
- 手动“立即沟通”不再吞掉真人点击后用非可信 `element.click()` 重放；现在保留原始可信事件给 BOSS，在冒泡末端只取消链接默认导航，并提前观察“已发送 / 留在此页”弹窗。
- 将带明确发送成功文案的“留在此页”弹窗纳入强成功证据；点击留在此页后只删除精确匹配的岗位，弹窗缺失或结果不明时仍保留。
- 将“职位标签不得承载消息页”提升为职位文档生命周期内的主世界持久保护，并增加后台多阶段稳定复查；无论批次是否已经启动，受保护标签进入 `/web/geek/chat` 或 `/job_detail/` 都会恢复并暂停，避免延迟 SPA 路由再次接管职位页。
- 达标后沟通过渡为约 3 秒，岗位间隔为约 5 秒；固定节奏不包含 JD 读取和 AI 响应耗时。
- 新增 JD 读取耗时、AI 服务商耗时和 JSON 修复标记，便于依据真实运行数据继续优化。
- 自动化会话最多保留 50 个岗位的精简判断字段，原始模型 JSON 不写入浏览器存储。
- 岗位条目在“定位”左侧新增独立“重新分析”：复用最近一次 JD 输入并行请求，只更新该岗位结果，不暂停或重排主队列，也不会自动触发沟通。

### 质量保障

- 新增真实模拟 `preventDefault()` 后 SPA 仍修改路由的运行时回归测试。
- 扩展后台导航边界测试覆盖详情页自动恢复，以及内容脚本已恢复时不重复后退。
- 新增跨协议输出预算、token 用量归一化、输入预算、JSON 修复流程、本地修复性能和分析会话存储体积测试。
- 新增分析速度配置/厂商能力映射，以及主队列继续运行时单岗位并行重新分析的回归测试。

## 0.9.0（2026-08-05）

### 新增

- 在岗位进度条目右侧新增 `×` 按钮，可提前关闭检测并将岗位移出当前投递列表。
- 已关闭岗位会记录在当前自动投递会话中，页面重新扫描或恢复任务时不会重新加入列表。
- 关闭岗位后，剩余岗位序号会立即连续重排。

### 优化

- 关闭正在分析或等待沟通的岗位时，使迟到的 AI 结果失效，并自动继续处理下一个岗位。
- 实际沟通步骤开始后暂时禁用关闭按钮，避免沟通结果处于不明确状态。
- 将自动投递确认合并到主按钮，增加启动中状态，避免重复点击和重复扫描。
- “定位下一个达标岗位”只定位真正达到最低分的岗位，不再跳转到待分析或未达标岗位。

### 质量保障

- 新增岗位关闭、任务续跑、序号重排和达标岗位定位回归测试。
- 更新扩展、演示配置和性能回归测试中的版本号为 `0.9.0`。
